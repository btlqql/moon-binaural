# 0.5.0 验证记录

## 分块空间渲染的两个宿主

本地源码版以两个独立 MoonBit 工程构建，均使用同一个公开 `SpatialRenderer`。夹具为四个方向、48 kHz、每耳 256 抽头的实测 HRIR。结果为两耳各自的最大绝对 PCM 误差。

| 宿主与输入 | 实际输出 | 与独立参考的误差 |
| --- | --- | --- |
| Chrome 157.0.8103.51 AudioWorklet，离线音频上下文。输入两个脉冲，帧 384 改变听者偏航。 | 双耳各 1,024 帧。第二个脉冲出现在帧 512，使用方向切换后的测量。 | 左 0，右 0 |
| Node.js v24.13.1，外部 JSON PCM 按 7、71、256、97、1 帧循环分块，末块按剩余长度裁剪。 | 731 帧输入得到两耳各 986 帧，其中尾音 255 帧。 | 左 3.33 × 10⁻¹⁶，右 2.78 × 10⁻¹⁶ |

浏览器自动验证从两份原始双耳测量和已知脉冲，直接构造预期输出。离线宿主逐样本与 Python 直接卷积对照，含全部尾音。Chrome 测试利用浏览器的真实 AudioWorklet 处理离线上下文，交互页面另支持耳机试听。 [复现入口](../README.md#复现两个独立宿主) · [独立宿主验证脚本](../scripts/verify_spatial_hosts.py) · [v0.5.0 版本入口](https://github.com/btlqql/moon-binaural/releases/tag/v0.5.0) · [独立宿主报告附件](https://github.com/btlqql/moon-binaural/releases/download/v0.5.0/spatial-hosts.json)

## 分块处理耗时

本地 Windows 11 / Intel64 Family 6 Model 183，Node.js v24.13.1，48 kHz，每耳 256 抽头。每组以 100 块预热，测量后续 500 块。稳态计时包含 `process_into`，淡化同时包含设置朝向。`p95`、`p99` 表示单块用时的分位数，单位为毫秒。

| 块长与条件 | p50 | p95 | p99 | 48 kHz 块时长 |
| --- | ---: | ---: | ---: | ---: |
| 128 帧，稳态 | 0.253 | 0.2995 | 0.363 | 2.667 |
| 128 帧，淡化 | 0.389 | 0.573 | 0.628 | 2.667 |
| 256 帧，稳态 | 0.508 | 0.609 | 0.723 | 5.333 |
| 256 帧，淡化 | 0.715 | 0.870 | 1.117 | 5.333 |

计时来自该主机上的 Node.js DSP 测试。浏览器设备回调、持续运行丢帧、设备延迟和主观定位效果均需独立测试。复现参数和原始数值保存在脚本生成的 `spatial-hosts.json` 中。

## 库测试和 0.4.1 兼容性

MoonBit v0.10.15+943464bfa 本地类型检查覆盖 JS、Wasm、Wasm-GC 和 Native。JS、Wasm、Wasm-GC 各通过 17 项测试，其中新增 5 项，涵盖听者转向、测量库数据归属、块间变向和快速更新、非法输入后状态保持、分次尾音与重置、采样率及抽头约束。本地 Native 实际运行需要 Windows C++ 工具链，可查公开 CI 的对应后端。 [CI](https://github.com/btlqql/moon-binaural/actions)

原有 `scripts/verify.py` 的独立卷积对照最大绝对误差约 1.11 × 10⁻¹⁵。旧《走廊》样片的双耳和普通声像 WAV 仍各为 744,255 帧，两份导出 PCM 的 SHA-256 与 0.4.1 证据一致。旧场景的增益返修仍将配平前超幅耳样本由 8 降为 0。 [0.4.1 旧验证与材料](https://github.com/btlqql/moon-binaural/releases/tag/v0.4.1)
